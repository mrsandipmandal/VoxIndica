# Project Roadmap — VoxIndica Studio

## Milestones & Completion Criteria

### Phase 1: Core Studio Workstation (Completed)
- [x] Multilingual TTS support for Bengali (West Bengal), Hindi, and Indian English.
- [x] Model capabilities registry with 5 verified Indic speech models.
- [x] Few-shot voice cloning studio with audio recording, validation, and mandatory consent verification.
- [x] Interactive waveform player with real-time seeking, playback speed control, and 16-bit PCM WAV export.
- [x] Dynamic provider orchestration for Local, Kaggle, and Google Colab workers with true ping heartbeats.
- [x] Benchmark matrix covering all 6 combinations with WER, MOS, Similarity, and RTF metrics.

### Phase 2: Tauri Desktop Wrapper Integration (Scaffold complete, installers pending)
- [x] Initialize `src-tauri` with a Tauri v2 Rust shell, loopback window and sidecar lifecycle (`docs/desktop.md`).
- [x] Package the application server as a Node SEA sidecar (`scripts/build-sidecar.mjs`).
  - The original roadmap named a PyInstaller/FastAPI sidecar. The Studio backend is Express (`server.ts`); the FastAPI service in `workers/` is GPU inference and cannot serve the UI. This item was deliberately implemented as a Node SEA.
- [ ] Test cross-platform builds: `.AppImage` (Linux), `.msi` (Windows), `.dmg` (Apple Silicon macOS).
  - `.github/workflows/desktop.yml` builds deb/AppImage, NSIS/MSI, and Apple Silicon DMG artifacts on GitHub runners.
  - Local Linux compile is blocked on this host: `libwebkit2gtk-4.1-dev`/`librsvg2-dev` are missing and `sudo` is unavailable. The sidecar binary itself is built and smoke-tested.

### Phase 3: Live Worker Notebook Bridges
- [x] Release production Jupyter notebooks for Kaggle and Google Colab with automated Cloudflare tunnel spinup.
  - Both notebooks are generated from `workers/voxindica_worker_core.py` via `python workers/build_notebooks.py`.
- [x] API-first provider layer: Kaggle API proxy (`/api/providers/kaggle/{test,launch,poll}`), real `/health` probes, and `WORKER_TIMEOUT_MS`-bounded worker routing for every task.
- [x] Implement end-to-end webhook callbacks for long-running batch inference.
  - Studio persists `/api/providers/batch` jobs under `data/batches/`, dispatches async worker batches, verifies HMAC-SHA256 callbacks, stores real WAV results, and exposes status/audio/cancel routes.
  - Dedicated loopback callback listener (default `127.0.0.1:3099`) exposes only the signed webhook; remote Kaggle/Colab workers require an explicit `VOXINDICA_PUBLIC_URL` tunnel and fail with `503` otherwise. No automatic tunnel is opened.
  - Worker adds `/batch`, `/batch/{id}` and `/batch/{id}/cancel`, signs item/batch events, retries delivery, and serializes model access with interactive synthesis.
  - Verified by `scripts/test/batch_webhook.mjs` (real Studio + fake worker + signed callbacks) and the extended `scripts/test/worker_smoke.py` batch contract checks.

### Phase 4: AI Creator Studio
#### Phase 4.0 — Project workspace (Completed)
- [x] `CreatorProject`/`ScriptDocument` types, zod contracts, UUID project store under `data/projects/`.
- [x] Atomic writes, 30 MB asset cap, consent record, ZIP export (`project.json`, `script.md`, assets).
- [x] `/api/creator/*` routes mounted before Vite; `data/` gitignored.

#### Phase 4.1 — Script engine (Completed)
- [x] Gemini → Groq → OpenRouter fallback with env model ids.
- [x] Schema validation before persistence; fallback only on rate limit/outage/timeout/network/invalid JSON.
- [x] Creator Studio tab: project wizard, scene editor, publishing package, provider health.
- [ ] Live generation verified with real provider keys (blocked on `.env`).

#### Phase 4.2 — Avatar spike (Notebooks ready, unverified)
- [x] Separate Kaggle SadTalker and MuseTalk notebooks generated by `workers/build_video_notebooks.py`; consented photo + 3–30s WAV → MP4, with `kernel-metadata.json`.
- [x] Run guide in `docs/creator/avatar-spike.md`; notebooks fail honestly and record wall time, VRAM upper bound, resolution and failure mode.
- [ ] Run both kernels on a real T4 and fill the result table (requires the user's Kaggle account and consented media).
- [ ] Integrate only the engine that produces a usable clip.

#### Phase 4.3 — Voice stage (Completed)
- [x] Per-scene synthesis through the existing worker `/clone_voice`; each take stored as a `scene_audio` WAV asset with a checkpoint in `project.voice`.
- [x] Reference audio validated as 3–30s RIFF/WAVE in the browser and again on the server; nothing synthesized without it.
- [x] Sequential job with real progress, cancel, per-scene regenerate, and resume of missing scenes after restart.
- [x] Verified against a contract stand-in worker: success, wrong token, cancel, ZIP export, restart recovery, and Playwright UI upload → synthesis → playback.
- [ ] Live synthesis on a real Kaggle/Colab T4 worker (needs the user's worker and reference clip).

#### Phase 4.4 — Presenter and video (Scene renderer completed)
- [x] Async, scene-checkpointed renderer with resumable jobs and FFmpeg assembly.
- [x] 1280×720 / 30 fps H.264 + AAC output from uploaded scene visuals and synthesized narration.
- [x] Landscape 1280×720, portrait 720×1280 and square 960×960 presets; dimension-aware clip reuse and ASS sizing.
- [x] Reuse only matching audio/visual fingerprints; real progress, cancel, restart recovery.
- [x] Honest failure states; no placeholder video.
- [ ] Presenter/avatar stage gated by `consent.json` and the T4 spike result.

#### Phase 4.5 — Captions, thumbnail, publishing (Completed)
- [x] SRT captions from real scene narration durations.
- [x] ASS captions with language-appropriate fonts, plus optional burned-in caption render.
- [x] Publishing pack export (description, tags, hashtags, real-timing chapters, disclosure, sources).
- [x] Thumbnail upload with prompt copy and approval-by-upload workflow.
- [x] AI thumbnail generation with Gemini behind explicit approval (needs `GEMINI_API_KEY`).

#### Phase 4.8 — Render format presets (Completed)
- [x] Landscape 1280×720, portrait 720×1280 and square 960×960 output.
- [x] Scene clips re-encoded when the preset changes; clips from another size are never reused.
- [x] ASS `PlayRes`, font size and margins follow the last completed render.
- [x] Preset selector in the render panel with honest re-render semantics.

#### Phase 4.9 — Music bed and audio polish (Completed)
- [x] Upload a licensed `music_bed` asset through the normal asset route.
- [x] Loop the track to the video length, attenuate by volume and duck it under narration with ffmpeg `sidechaincompress`.
- [x] Optional `loudnorm` to −14 LUFS; `amix` uses `normalize=0` so narration is not halved.
- [x] Audio settings snapshotted on the render job and included in the completed-render `409`.
- [x] Render panel music select, upload, preview, volume slider and normalize checkbox.
- [x] Verified mix levels (FFT), volume scaling, ducking depth, normalization gain and validation errors.
